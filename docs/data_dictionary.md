# Data Dictionary

Documentation for every column across the pipeline stages. The dataset is
generated by `scripts/generate_data.py` (seeded, reproducible), cleaned by
`src/etl.py`, and featurized by `src/features.py`.

---

## Stage 1 — Raw (`data/raw/ecommerce_orders.csv`)

100,000 rows × 13 columns.

| Column | Type | Description / allowed values |
|---|---|---|
| `Order ID` | str | Unique order identifier, `ORD000001`..`ORD100000` |
| `Customer ID` | str | Anonymized customer id, `CUST####` (2,302 distinct) |
| `Platform` | category | `Blinkit`, `JioMart`, `Swiggy Instamart` |
| `Order Date & Time` | datetime | Order timestamp, `YYYY-MM-DD HH:MM:SS`, 2024-11-01 → 2025-01-31 |
| `Promised Delivery (Minutes)` | int | Per-category SLA + jitter, range 12–48 |
| `Actual Delivery (Minutes)` | int | Promised + overrun/early margin, range 3–109 |
| `Product Category` | category | `Grocery`, `Dairy`, `Beverages`, `Snacks`, `Personal Care`, `Fruits & Vegetables` |
| `Order Value (INR)` | int | Log-normal order value, range 50–2000 |
| `Items Count` | int | Items in order, range 1–20 |
| `Customer Feedback` | str | Free-text feedback (23 distinct phrases, probabilistically tied to rating) |
| `Service Rating` | int | 1–5 (latent satisfaction, never forced) |
| `Delivery Delay` | str | `Yes`/`No` — derived as `actual > promised` |
| `Refund Requested` | str | `Yes`/`No` — probabilistic given rating/delay/category/value |

---

## Stage 2 — Clean (`data/processed/orders_clean.csv`)

Produced by `src/etl.py`. 100,000 rows × 16 columns.

| Column | Type | Description |
|---|---|---|
| *(all raw columns)* | | Type-coerced, stripped, validated |
| `is_delayed` | bool | **Derived** `Actual > Promised`; single source of truth (asserted == `Delivery Delay`) |
| `order_weekday` | int | Day of week, Monday=0 … Sunday=6 |
| `order_hour` | int | Hour of day, 0–23 |

The clean table mirrors `SQL/schema.sql` (the PostgreSQL `orders` table).

---

## Stage 3 — Features (`data/processed/features.csv`)

Produced by `src/features.py`. 100,000 rows × 21 columns. All numeric, model-ready.

| Column | Type | Description |
|---|---|---|
| `order_id` | str | Order id (join key, excluded from modeling) |
| `minutes_late` | int | `max(actual - promised, 0)` — how late, 0 if on time |
| `order_value` | int | Order value in INR |
| `items_count` | int | Items in order |
| `promised_minutes` | int | Promised delivery minutes |
| `weekday` | int | Day of week 0–6 |
| `hour` | int | Hour 0–23 |
| `value_bucket` | category | `low`/`mid`/`high`/`premium` (bins 0/300/600/1000/5000) |
| `delay_and_high_value` | int | Interaction: delayed AND value ≥ 800 |
| `service_rating` | int | 1–5 (baseline's dominant signal; keeps model comparison apples-to-apples) |
| `is_delayed` | int | 0/1 (baseline's secondary signal) |
| `platform_Blinkit`, `platform_JioMart`, `platform_Swiggy Instamart` | int | One-hot platform |
| `category_*` | int | One-hot category (6 columns) |
| `refund_requested` | int | **Target** — 1 if refund requested (18.7% positive) |

---

## Stage 4 — Model artifacts (`models/`)

| Artifact | Description |
|---|---|
| `metrics.json` | All metrics (accuracy, precision, recall, F1, ROC-AUC, CV AUC, confusion matrix, feature importance) for logistic regression, random forest, and the rule-based baseline |
| `baseline_predictions.csv` | Order-level rule-based scores + predictions for all 100k rows |
| `refund_model.joblib` | Saved random forest + feature column list (loaded by the dashboard) |

Model inputs are `_feature_cols(features)` in `src/model.py`: all numeric columns except `order_id`, `value_bucket`, and `refund_requested`.
